    Participants

    Invitations (optional)

    The space is open: anyone who signs in joins it. Invitation links are still useful to add another admin, or if you switch the space to invitation-only.

    Breakdowns

    Optional profile questions

    Asked once when people join, all optional. Results show how each group rated a change, but groups never block one, and groups with fewer than 5 answers are not shown. Edit the list in community.js and the labels in lang/*.js.

    Opinion groups found from the votes, as in Polis, can be added later as another breakdown. They need about 100 active participants.

    AI help Off by default. Concerns, scores and compromises never use AI.

    After the round

    Publish, train and report

    • Publish the new charter version
      Endorsed changes, and bridges endorsed in the bridge phase, become a fixed version with its dissent record. The Charter page shows it as tracked changes.      End of round
    • Review the test cases
      Admins mark the test cases of adopted changes as confirmed before training. Only admins can change a test case’s status.      One week
    • Check the safety floor
      The new version must still pass every floor case. A change that breaks one is held back for review.      Pipeline
    • Split the test cases 80/20
      Fixed by each case's ID, so nobody can move a case between training and testing.      Pipeline
    • Fine-tune the model
      Model set in kit.config.json; the default is Apertus v1.1 1.5B, which fits a free cloud GPU.      Pipeline
    • Publish the scorecard
      Before and after, on held-out cases and the safety floor.      Pipeline
